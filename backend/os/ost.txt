PROCESS CONTROL BLOCK(PCB):

| **PCB Field**                        | **One-Line Explanation**                                                                                       |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| **Process ID (PID)**                 | A unique number assigned by the OS to identify a process.                                                      |
| **Process State**                    | Stores the current state of the process (New, Ready, Running, Waiting, or Terminated).                         |
| **Program Counter (PC)**             | Stores the address of the next instruction the CPU will execute.                                               |
| **CPU Registers**                    | Stores the current values of CPU registers so the process can resume correctly after a context switch.         |
| **CPU Scheduling Information**       | Stores scheduling details like priority, time slice, and queue information used by the CPU scheduler.          |
| **Memory Management Information**    | Stores information about the process's memory, such as page tables, base/limit registers, or memory map.       |
| **Accounting Information**           | Stores resource usage details like CPU time, process creation time, and user ID for monitoring and accounting. |
| **I/O Status Information**           | Stores information about the process's open files, I/O devices, and pending I/O operations.                    |
| **Parent/Child Process Information** | Stores the IDs and relationships of the parent process and any child processes.     


| Ready                              | Waiting                              |

| Waiting for CPU                    | Waiting for an event/I/O             |
| Can run as soon as CPU is assigned | Cannot run until the event completes |


Q7. Is PCB stored in RAM or Disk?

Answer:
PCB is stored in RAM, specifically in the kernel's memory, because the OS needs fast access to it.     

Q: Does a child process have its own PCB?

Answer:
Yes. Every process, including parent and child processes, has its own Process Control Block (PCB).
The child's PCB stores its own PID, state, program counter, registers, memory information, scheduling information, and also contains
the Parent PID to identify its parent process.                      |

Q: Is the PCB of a child process different from the parent's PCB?

Answer:
The PCB format is the same, but the contents are different. Each process has its own unique PID, process state, program counter, CPU registers, scheduling 
information, and memory information. The parent PCB stores references to its children, while the child PCB stores the PID of its parent.

1. What are thread models?

Answer:
Thread models define how user-level threads are mapped to kernel-level threads.

2. Name the three thread models.

Answer:

Many-to-One
One-to-One
Many-to-Many
3. Which thread model is the fastest?

Answer:
Many-to-One has the lowest overhead because only one kernel thread is managed.

4. Which thread model supports multicore processors?

Answer:
One-to-One and Many-to-Many support multicore processors because multiple kernel threads can execute simultaneously.

5. Which thread model is used by Linux and Windows?

Answer:
The One-to-One model.

6. What is the disadvantage of the Many-to-One model?

Answer:
If one thread performs a blocking operation, the entire process blocks because all user threads share a single kernel thread.

7. Which thread model is more complex?

Answer:
The Many-to-Many model because it requires dynamic mapping between user threads and kernel threads.

8. Why is the One-to-One model popular?

Answer:

Supports true parallelism.
Better responsiveness.
Efficient scheduling by the operating system.
Ideal for multicore processors.

Q1. What is the Ignore approach?
Answer:The Ignore approach *********(Ostrich Algorithm)******** assumes deadlocks are rare and does not attempt to prevent, avoid, or detect them. 
If a deadlock occurs, it is resolved manually, such as by terminating the affected process or restarting the system.

Q2. Why do operating systems ignore deadlocks?
Answer:Because continuously checking for deadlocks introduces overhead. Since deadlocks are relatively rare in many workloads, ignoring them 
can improve overall system performance.

Q5. Difference between deadlock and starvation?
Answer: In a deadlock, processes wait for each other forever. In starvation, a process waits indefinitely because other processes
keep getting the resource.

Q8. What is Banker's Algorithm used for?
Answer: It is a deadlock avoidance algorithm that grants resources only if the system remains in a safe state.

Q9. Why is it called Banker's Algorithm?
Answer: Like a bank approving loans only when it can satisfy all customers eventually, the OS allocates resources only if it can
 guarantee safe completion.

Q10. Which is better: prevention or avoidance?
Answer: Prevention is simpler but can reduce resource utilization. Avoidance is more efficient but requires additional checks and 
knowledge of maximum resource needs.

Q10. What is FIFO page replacement?
Answer: FIFO replaces the page that has been in memory the longest.

Q11. What is LRU?
Answer: LRU replaces the page that has not been used for the longest time in the past.

Q12. What is the Optimal page replacement algorithm?
Answer: Optimal replaces the page that will not be used for the longest time in the future. It gives the minimum page faults but is not practical because future memory accesses are unknown.

Q13. Which page replacement algorithm is best?
Answer: The Optimal algorithm has the fewest page faults theoretically. In practice, LRU is widely used because it approximates Optimal without requiring future knowledge.

Q14. What is Belady's anomaly?
Answer: Belady's anomaly is the phenomenon where increasing the number of page frames causes more page faults. It can occur with FIFO but not with LRU or Optimal.

	IPC (Inter-Process Communication) means the mechanisms provided by the operating system that allow two or more processes to exchange data and coordinate with each other.

Common IPC mechanisms:
	1.Shared Memory
	2.Message Passing
	3.Pipe
	4.Named Pipe (FIFO)
	5.Socket

1.Shared Memory → Processes communicate by accessing the same memory area.
2.Message Passing → Processes communicate by sending and receiving messages.
3.Pipe = mainly communication between related processes on the same machine.
4.Socket = communication between processes, including processes on different machines over a network.
